# Interoperability

## Canonical trace boundary

Kochab accepts OTLP trace export requests and projects them into a loss-preserving internal view. The canonical semantics are:

1. OpenTelemetry trace/span identity, parentage, time, status, resource, scope, attributes and events;
2. OpenTelemetry GenAI operations such as `invoke_agent`, `invoke_workflow`, `plan` and `execute_tool`;
3. OpenInference span kinds, input/output fields, annotations and evaluations;
4. `gen_ai.evaluation.result` events and Braintrust `braintrust.scores` attributes.

The OpenTelemetry GenAI Agent conventions are still marked development. Unknown attributes and events are therefore retained instead of being normalized away. Input and output attributes can contain private data; sampling, filtering and redaction remain the responsibility of the host's OpenTelemetry pipeline.

Supported transports:

- OTLP/HTTP protobuf (`application/x-protobuf`);
- OTLP/HTTP JSON (`application/json`), optionally gzip-compressed;
- OTLP JSON or JSONL export files.

The receiver is available at `http://127.0.0.1:4318/v1/traces` while `kochab daemon` is running.

## Trace ecosystem matrix

| Producer or platform | Compatibility path | Scope |
|---|---|---|
| OpenTelemetry SDKs and Collector | Send or fan out OTLP/HTTP to kochab | Native |
| OpenInference instrumentors | OTLP with OpenInference attributes | Native, including annotations/evaluations |
| Arize Phoenix | Fan out the same OpenInference OTLP stream | Native transport and semantics |
| LangSmith | Fan out its OpenTelemetry stream | Trace structure, GenAI and OpenInference attributes |
| MLflow 3.6+ | Fan out OpenTelemetry GenAI spans | Native transport and GenAI semantics |
| Braintrust | Fan out OTLP; `braintrust.scores` is recognized | Trace structure, GenAI and scores |

Kochab does not silently scrape an existing SaaS history. For continuous evolution, configure the producer or an OpenTelemetry Collector to send a copy of new traces to both the existing backend and kochab.

Example Collector fan-out:

```yaml
receivers:
  otlp:
    protocols:
      http: {}

exporters:
  otlphttp/kochab:
    endpoint: http://host.docker.internal:4318
  otlphttp/existing:
    endpoint: ${env:EXISTING_OTLP_ENDPOINT}
    headers:
      Authorization: ${env:EXISTING_OTLP_AUTHORIZATION}

service:
  pipelines:
    traces:
      receivers: [otlp]
      exporters: [otlphttp/kochab, otlphttp/existing]
```

## Evaluation ecosystem matrix

The execution boundary is a command argument array, never a shell string. Placeholders provide the candidate surface and selected cases. The result parser is independent from the runner.

| Framework family | `eval.format` | Notes |
|---|---|---|
| Kochab-native/custom | `kochab` | JSON object with host-defined `passed` |
| Ragas/custom dataframe jobs | `jsonl` | One normalized sample per line through a thin runner |
| Promptfoo | `promptfoo` | Reads v3 JSON envelopes and result arrays |
| pytest / DeepEval / other test runners | `junit` | Use their JUnit XML output option |
| Inspect AI | `inspect` | JSON logs directly; `.eval` through the installed `inspect_ai.log` API |
| DSPy / GEPA / MLflow / LangSmith / Phoenix / Braintrust SDK evaluations | `kochab` or `jsonl` | Thin runner preserves the framework's native evaluator and exports normalized results |

Useful placeholders:

- `{python}`: active Python interpreter;
- `{surface_dir}`: isolated materialization of the requested candidate version;
- `{case_ids}`: comma-separated selected case ids;
- `{result_path}`: exact result file inside the isolated tree;
- `{result_dir}`: directory for frameworks that choose their own result filename.

`result_glob` selects the newest file under `{result_dir}`. This is useful for Inspect AI, whose log filename is generated by the framework.

List every local evaluator, rubric, dataset, or dependency directory in
`eval.dependency_paths`. Onboarding hashes those files together with the case catalog,
criteria, binding, and tunable source units so a frozen run cannot silently change its
measurement contract.
