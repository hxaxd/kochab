# 能力改进架构图：讨论稿

[可编辑源文件](capability-architecture.drawio) · [SVG](capability-architecture.svg) · [PNG](capability-architecture.png) · [PDF](capability-architecture.pdf)

本稿采用固定的三列网格。中间是执行系统、Benchmark 和执行证据；上方是 Agent 改进、任务扩展和评判校准；下方是学习材料、模型训练和独立验证。模块用明确边界与标题条表示，证据和材料用叠页形态表示，独立验证用菱形表示，人工输入用暖色表示。同行元素的基线、高度与主要连接位置统一。

图从真实需求与使用出发：任务合成、审核、入集；模型驱动 Agent 通过工具与环境行动，留下轨迹；验证器在 Rubric 等标准下生成判断。判断既形成评测反馈，也经奖励映射进入 RL。评测反馈支持任务扩展与 Agent 优化；人工对照与执行判断支持元评估，再修订标准。专家示范和执行经验经加工进入 SFT 或偏好优化，领域素材支持中间训练。模型和 Agent 候选均需独立验证。

这是待讨论的职责关系，不代表现有代码已实现，也不表示自动运行就足以实现 RSI。图中的训练路径可独立采用；评测、开发和训练用的任务不得直接充当独立测试。

图中橙色节点表示人类经验常见的入口：需求与品位、专家对照、示范纠正和领域知识。它们可以由人机协作提供；图不将人类判断视为天然正确。Rubric 是标准，Judge 是执行者，判断结果才可能是标量、向量或结构化回答。

## 图与正文的分工

图保留对象、数据流、反馈回路和必要边界。工具覆盖行为空间的要求、环境随机性的处理、验证器作用范围、数据版本与去重方法、判断一致性与正确性的区别、训练数据质量和奖励投机问题，留待正文展开。任务审核、材料整理和元评估也需要各自的质量证据，这些细节在后续讨论中逐步确定。

连线按主流程与局部反馈分层，轨迹与判断合入一个证据边界。上方取消横贯全图的共享反馈线：执行反馈、失败样本和判断样本分别从相邻模块进入改进步骤。评判校准反向排列，使 Rubric 的输出靠近 Benchmark，避免交叉。细虚线表示反馈或设施复用，实线表示任务与产物流转。模型候选和 Agent 候选分别单向进入独立验证，图中不展开采用流程。

图中文字按职责精简：Agent 内列出 Context、Tools、自进化；验证器仅保留 Agent as a Judge 与 Rubric；训练分为中间训练、SFT、RL。脚本验证、偏好优化等更完整的分类与机制留待正文展开。

这些反馈箭头指向职责边界，不声称模块在内部独立生成所有反馈；例如执行系统的改进也会使用评测判断。Benchmark 内部的初始化、工具调用、取证依赖不逐条展开；环境复用与奖励供给合为训练入口。这是职责与产物流向图，不是逐次调用的时序图。

源文件以 `.drawio` 为准。PNG 和 PDF 已按实际渲染检查。SVG 由矢量 PDF 转换，文字转为轮廓，以避免 README 中的中文字体与 foreignObject 兼容问题；文字编辑请回到源图。原文章和原配图未替换。

## 模块覆盖：与公开生产流程对照

以下是后续讨论候选，本轮未加入图中：

- **训练数据生产**：教师模型生成示范、人工标注和修订。目前图中显式表达了任务生成与材料筛选，训练样本生产本身尚未独立表达。Llama 3 报告描述了逐轮合成数据、偏好标注和回答修订，见[第 4.2 节](https://arxiv.org/html/2407.21783v3#S4.SS2)。
- **环境构建**：产出可执行环境、配套工具和验证程序。目前图中只有环境成品及其复用。MiMo 公布了任务、验证器类别、Docker 镜像和训练代码；据此，本图可将这些产物的构建职责单列，见[官方环境说明](https://huggingface.co/datasets/XiaomiMiMo/MiMo-V2.6-RL-oss/blob/main/README.md)。
- **奖励模型训练**：产出专门的评分模型，区别于现有的 Rubric 修订。DeepSeek-V3 报告明确描述用偏好数据从 SFT 检查点训练奖励模型，见[第 5.2.1 节](https://arxiv.org/html/2412.19437v2#S5.SS2.SSS1)。

上述模块划分是对本图的设计建议，不声称对应各公司的实际组织边界。完整模型公司还涉及预训练、模型架构研发、训练与推理基础设施；是否纳入应服从本仓库对能力改进链路的范围定义。

## 参考资料与采用范围

这张图是针对 Kochab 教学目标的综合设计，并非复刻某篇综述的分类图。来源支持局部概念，不构成对完整 RSI 路径的实证证明。

1. **A Survey of Self-Evolving Agents: On Path to Artificial Super Intelligence**，Gao 等，[arXiv:2507.21046](https://arxiv.org/abs/2507.21046)，参阅 [v1 全文](https://arxiv.org/html/2507.21046v1)。采用的覆盖维度：模型、上下文与记忆、提示词、工具、架构；外部反馈驱动演化；评估应考虑泛化、保持与效率。对应执行框架、归因优化和独立验证。
2. **A Survey on LLM-as-a-Judge**，Gu 等，[arXiv:2411.15594](https://arxiv.org/abs/2411.15594)，参阅 [v6 全文](https://arxiv.org/html/2411.15594v6)。采用的覆盖维度：评分、是非、比较和选择等输出；提示词中的评价标准；与人类判断的一致性、偏差与对抗稳健性等元评估。对应验证器、判断结果和元评估。
3. **On LLMs-Driven Synthetic Data Generation, Curation, and Evaluation: A Survey**，Long 等，[arXiv:2406.15126](https://arxiv.org/abs/2406.15126)，参阅 [v1 全文](https://arxiv.org/html/2406.15126v1)。采用的覆盖维度：生成、筛选、标签改善与数据评估；数据自身质量与下游训练收益应分别评价。对应任务合成、材料整理和模型训练。
4. **XiaomiMiMo / MiMo-V2.6-RL-oss**，[官方环境说明](https://huggingface.co/datasets/XiaomiMiMo/MiMo-V2.6-RL-oss/blob/main/README.md)。作为第四层作业的工程参考：代码任务、可执行测试、环境镜像与训练代码分别交付；本图不声称复现了其训练系统。
