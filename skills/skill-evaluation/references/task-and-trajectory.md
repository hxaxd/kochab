# 任务与过程评测

来源：Google agents-cli 的评测方法，按通用任务结果与过程记录整理。此参考不依赖 Google CLI、云端评测服务或特定智能体框架。

## 按目标选择证据

分别考察任务是否完成、产物质量与事实依据、工具选择及参数、执行效率、交互中的约束遵守。每项都对应当前任务真实需要的结果，按案例选择；不把所有维度固定塞进每次评测。

最终回答正确时，仍检查重要动作是否真的发生；执行轨迹与示范不同但同样正确、有效时，不凭路径不同判失败。步骤数、调用数和时长只有结合任务质量才能说明效率；零温度设置也不保证完全确定。

可以由确定性工具核实的属性，用工具检查；开放质量判断写明评分依据和产物证据。工具调用返回数据是否支持回答，需要逐项核对。现有 grading.json 的期待项可带维度字段或在 text 中说明维度，汇总仍依据真实条目；不同任务的综合通过率不能脱离组成维度解释。

## 数据集与回归

从实际请求、历史失败和重要边界中选案例，明确输入、环境、目标和可接受结果。保留部分案例不参与修改过程，只在准备交付时检查，以区分真实泛化与对调优样本的适配。

用同一组案例比较修改前后，不随结果改变成功标准。发现测试本身错误时，记录依据，修正后对两种条件同样重新评分。波动结果检查模型设置、环境和评价依据，必要时在已授权范围内重复运行；不能通过删除波动案例来制造改善。

每次改动针对已观察的失败：任务未完成查缺失动作或提前结束，工具错误查描述、参数和选择条件，事实错误查引用与返回数据，重复执行查停止条件。修复后检查相关案例和必要的其他案例是否退步，展示逐项差异、未运行项和未知指标。

## 多轮与多模态

按完整交互的用户目标评价多轮任务，不把每轮响应单独正确等同于整体成功。需要图像、声音或视频证据时，确认评审实际看到了对应模态；只有文字记录时明确证据范围。模型裁判的结论需要可追溯依据，不能仅靠一个分数。

批量模型运行、独立模型裁判、用户模拟和自动提示词优化均服从本技能的执行授权；已存在的记录可由当前执行者分析。
